## For future Claude

Daily note for 2026-08-22. The umu team told the owner they only want
umu-database entries for games that actually require umu fixes - which is the
README's own opening paragraph, missed in earlier sessions. That reframed the
whole contribution half of [[wiki/projects/gamebus-presenced|gamebus-presenced]]:
a protonfix scope gate was built (uncommitted), the submitted PR #151 turned
out not to qualify, and a survey of every game-identity data source went into
the vault - which incidentally proved that icons and cover art are already in
hand.

## Work done

Full detail:
[[wiki/logs/2026-08-22 - gamebus-presenced umu Scope Gate]].

- **The scope rule** (umu team, 2026-08-22): the database collects games that
  require fixes in Proton; games that run out of the box "have no need be
  added". Verified against the README verbatim. Consequence: PR #151 (Control)
  does not qualify - no `gamefixes-steam/870780.py` upstream, and no 870780
  branch in Proton's own script either.
- **Scope gate built** (uncommitted, gate green at 310 tests): a `ProtonFixes`
  index from one GitHub tree request (488 files, 377 ids), cached and
  refreshed weekly, `GAMEBUS_UMU_PROTONFIXES` for a local checkout; `--verify`
  records it per entry; exports submit only games with a fix and link the fix
  in the evidence. Live result on a copy of the real stash: none of the 15
  misses qualifies.
- **Honesty split found by running it**: "no protonfix" means "runs out of the
  box" only under a firm id (database's own, or a detectable.json Steam sku).
  Under a guessed slug it means "nothing shows this game needs umu" - a fix
  could sit under an appid we never learned.
- **Data-source survey**:
  [[wiki/concepts/Game Identity Data Sources]]. No universal database exists
  and no upstream accepts what this project learns - Discord's file is closed
  to contributions, umu's is scoped to fix-needing games, Lutris's API is
  read-only with no store-codename schema. So: a corrections overlay layered
  like shared-helpers.txt, never a fork.
- **Artwork is already in hand** (measured): detectable.json carries
  `icon_hash` for 19,752 of 23,900 entries and `cover_image_hash` for 16,758,
  and the Discord CDN URL built from entry id plus hash resolves. Richer
  presence needs no new source - see
  [[wiki/concepts/Richer Presence Over the Bus]].
- **Lutris as a second opinion**: its `steamid` matched our
  detectable-derived drafts exactly on all three games checked. Useful for
  firming up a drafted id; useless as a contribution target.

- **Scope gate committed** as `e41d657` on master (11 files, +813/-57) once the
  owner closed the exploration. Gate re-run green before committing: fmt,
  clippy `-D warnings`, 310 tests.
- **The corrections repo got designed** in the evening's exchange:
  [[wiki/decisions/adr-010-corrections-repo-toml-pages-built-artifacts]]. One
  TOML page per game, PRs instead of an API, CI lint from our own validator,
  and condensed artifacts (Parquet, SQLite, JSON, umu-shaped CSV) built by a
  DuckDB pass and shipped as release assets. The owner's own framing drove the
  file-per-game shape: umu-database keeping "it all in a file everyone writes
  to" is the failure to avoid. Licenses verified: DuckDB and its SQLite
  extension are both MIT.
